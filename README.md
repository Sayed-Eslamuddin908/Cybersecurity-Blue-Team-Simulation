# 🔵 Blue Team Simulation

The **Blue Team Simulation** is the defensive component of the cybersecurity lab. It is designed to monitor, detect, investigate, and respond to activity generated by the Red Team Simulation.

The Blue Team uses **Wazuh, Sysmon, Suricata, Wireshark, Sigma, and MITRE ATT&CK** to provide endpoint and network visibility.

# 1. Wazuh Installation on Kali Linux

Update Kali:

```bash
sudo apt update
sudo apt upgrade -y
```

Download the Wazuh installation assistant:

```bash
curl -sO https://packages.wazuh.com/4.14/wazuh-install.sh
```

Make it executable:

```bash
chmod +x wazuh-install.sh
```

Install Wazuh:

```bash
sudo bash ./wazuh-install.sh -a
```

The `-a` option performs an all-in-one Wazuh installation.

# 2. Wazuh Agent Authentication

After Wazuh installation, create an agent for the target system.

Open the Wazuh agent manager:

```bash
sudo /var/ossec/bin/manage_agents
```

Select:

```text
A
```

Add the agent.

Example:

```text
Agent Name: Windows-PC
Agent IP: 192.168.163.136
```

After creating the agent, select:

```text
E
```

to extract the authentication key.

Copy the generated key securely.

### Authentication Key Location

Wazuh stores agent keys on the Manager at:

```bash
/var/ossec/etc/client.keys
```

View the keys:

```bash
sudo cat /var/ossec/etc/client.keys
```

> ⚠️ **Never upload `client.keys` to GitHub or expose it publicly.**

Restart Wazuh Manager:

```bash
sudo systemctl restart wazuh-manager
```

Check the Manager:

```bash
sudo systemctl status wazuh-manager
```

List registered agents:

```bash
sudo /var/ossec/bin/manage_agents -l
```

# 3. Sysmon Installation on Windows

**Sysmon (System Monitor)** provides detailed Windows endpoint telemetry that can be collected by the Wazuh Agent.

Sysmon can record information such as:

- Process creation
- Process termination
- Network connections
- File creation
- Registry activity
- DLL/image loading
- Driver activity
- DNS activity

## Download Sysmon

Download Sysmon from Microsoft's Sysinternals collection and extract it.

For example:

```text
C:\Sysmon
```

Place your Sysmon configuration file in the same directory:

```text
C:\Sysmon\sysmonconfig.xml
```

Open **PowerShell as Administrator**:

```powershell
cd C:\Sysmon
```

Install Sysmon:

```powershell
.\Sysmon64.exe -accepteula -i sysmonconfig.xml
```

### Command Explanation

```text
-accepteula
```

Accepts the Sysinternals license agreement.

```text
-i
```

Installs Sysmon as a Windows service.

```text
sysmonconfig.xml
```

Specifies the Sysmon configuration file.

---

## Verify Sysmon

Check the service:

```powershell
Get-Service Sysmon64
```

You should see:

```text
Status    Name
------    ----
Running   Sysmon64
```

You can also check:

```powershell
sc.exe query Sysmon64
```

---

## View Sysmon Events

Open:

```text
Event Viewer
```

Navigate to:

```text
Applications and Services Logs
└── Microsoft
    └── Windows
        └── Sysmon
            └── Operational
```

The events are available under:

```text
Microsoft-Windows-Sysmon/Operational
```

---

## Update Sysmon Configuration

If Sysmon is already installed:

```powershell
.\Sysmon64.exe -c sysmonconfig.xml
```

View the current configuration:

```powershell
.\Sysmon64.exe -c
```

Uninstall Sysmon if required:

```powershell
.\Sysmon64.exe -u
```

> ⚠️ Run Sysmon commands from **Administrator PowerShell**.

# 7. Wazuh Troubleshooting Commands

Check Wazuh Manager:

```bash
sudo systemctl status wazuh-manager
```

Check all Wazuh components:

```bash
sudo systemctl status wazuh-manager wazuh-indexer wazuh-dashboard
```

Check Wazuh processes:

```bash
sudo /var/ossec/bin/wazuh-control status
```

Test the Wazuh configuration:

```bash
sudo /var/ossec/bin/wazuh-analysisd -t
```

Monitor Wazuh logs:

```bash
sudo tail -f /var/ossec/logs/ossec.log
```

Search for errors:

```bash
sudo grep -i "error" /var/ossec/logs/ossec.log
```
